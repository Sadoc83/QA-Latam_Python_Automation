## Convenciones para nombrar el código

1. [ ] Los nombres de las variables se escriben en formato `snake_case` y describen claramente su propósito.
2. [ ] Las constantes se escriben en mayúsculas.
3. [ ] Se utilizan comentarios para explicar bloques de código importantes.
4. [ ] El código se organiza de forma modular, importando bloques de código reutilizables cuando sea necesario.
5. [ ] No se utilizan funciones de espera innecesarias que prolonguen la ejecución de las pruebas.
6. [ ] Se sigue una convención para nombrar las pruebas: los nombres comienzan con `test_` y describen claramente el escenario que se está probando. Los títulos de las pruebas se proporcionan en las instrucciones de la tarea.
